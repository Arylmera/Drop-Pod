Three lines that mutate a final field

class Account {
    private final String iban;
    Account(String iban) { this.iban = iban; }
    String iban() { return iban; }
}

var a = new Account("old");
Field f = Account.class.getDeclaredField("iban");
f.setAccessible(true);           // deep reflection
f.set(a, "new");                 // writes into a final
a.iban();                        // "new", no warning

Ordinary class, final instance field — on today's LTS (JDK 25) this succeeds silently

What reflection actually costs

1Speed

Every call re-checks access and re-converts arguments before it invokes anything.

2Safety

No compile-time check: a rename breaks at run time, not at build time.

3Integrity

Deep reflection can read private state and rewrite fields declared final.

4AOT / native

GraalVM native-image needs every reflective access declared up front.

5Readability

The behaviour is invisible to a human just reading the class.

Coupling, graded by depth

Depths to avoid
  • Intrusive: reflection, or casting an interface to its implementation
  • Functional: A quietly breaks B — the common default
The target: contract
  • Explicit: a function signature, a REST API, a schema
  • An interface is not a stronger contract — the signature already was
