Single source of truth: before, during, after

goodSpec — before

Written before code. Good for humans and agents alike — precise enough that both can act on it.

openCode — during

Always has bugs, and they become the truth. Carries no context: why this ORDER BY, why this version.

openDocs — after

Only as good as the context it carries. Worthless if it just restates the code in prose.

A spec is a use case, not a document

1Actor & precondition

Who triggers it, what must already be true — becomes the prompt's context.

2Main flow

The steps in order — becomes the implementation.

3Alternative flows

The edge cases — exactly what an agent tends to miss on its own.

4Acceptance criteria

Written as checks, not prose — becomes the test suite directly.

Generate a diagram, don't draw one

Ask for an opinion
  • A hand-drawn diagram, reviewed once
  • Drifts the moment the code moves on
  • The agent inherits a picture, not a fact
zero drift
Ask for a script
  • A deterministic script produces the view
  • Re-run it and it's honest again, for free
  • The agent reads a fact, not an opinion

What docs must carry

  • Architecture in diagrams, never in a source comment
  • APIs in Javadoc, internals in comments — never mixed up
  • Decisions, and the rejected designs, and why
  • Warnings: “single-thread only, because...”
!

Rewriting code as prose is pointless. Docs exist for what code cannot say at all.

Key takeaways

  1. 1The spec is the source of truth before coding — precise enough for a human and an agent to both act on it.
  2. 2Rules and skills rot. Keep them lean, delete lines, push anything deterministic into scripts, not prose.
  3. 3Code alone never carries the why. Docs matter more, not less, now that an agent reads them too.
