Three approaches that don't pass the bar

1A container

Shares the host kernel; a coding agent needs its own Docker daemon for tests and Testcontainers, so the host daemon is handed over too — as good as root.

2Allow/deny command lists

A cat-and-mouse game: block rm -rf and the agent writes it into a generated script instead. A false sense of security, not a boundary.

3AI vetting the AI

A classifier model watching the acting model is an opinion, not a wall — and an opinion can be talked around.

Scope the sub-agent, not the prompt

@Service   // exposed only to the "Orders" sub-agent's MCP
class OrdersAgentTools {

    @Tool
    OrderSummaryDto findOrder(String orderId) {
        return orderRepo.findById(orderId)
            .map(OrderSummaryDto::from)
            .orElseThrow();
    }
    // no cancelOrder, no refund: those
    // methods don't exist on this bean
}

A supervisor delegates to Orders / Pay / Support sub-agents, each its own MCP — a mistake in Orders has nothing to reach in Pay

Scoping the machine, not just the tool

1Containment

Its own kernel per agent — hardware-enforced, not a shared container — with its own Docker daemon inside for tests and builds.

2Filesystem scope

Only the chosen directories are mounted; a reporting-service ticket should never see ~/.m2/settings.xml or ~/.ssh.

3Network policy

Deny by default; only the registries and services the task needs are reachable, logged.

4Secrets never inside

Secrets stay on the host; the only thing injected is a dummy value swapped for the real one on the way out — the agent can't print what it never holds.

Securing what the agent calls out to: five knights

11. Leaked secrets

A prod credential pasted into chat can sit in a server's logs forever — never paste secrets; check what gets logged.

22. A server as double agent

An unofficial copy siphoning keys and data — verify it's the official server before trusting it.

33. Black-box CVEs

A vulnerable library inside the server; the attacker hits the server, not the model — run SCA and DAST against it.

44. Context pollution

A hundred pages fetched for one paragraph, or injected data read as fact — one scoped server per sub-agent, not a global one.

55. Sprawl

Ten servers, three doing the same job, no shared policy — one hardened, governed gateway instead.

Key takeaways

  1. 1Scope what it can reach — files, network, secrets, tools — before it acts, and let no one edit that scope, not even it.
  2. 2Put a different model between the author agent and the human; dim human review by risk tier, never by trust alone.
  3. 3Judge it by outcomes — change-failure rate, not felt speed — the same measure every earlier talk used.
